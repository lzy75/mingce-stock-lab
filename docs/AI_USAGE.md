# AI 使用与验证记录

## 工具及职责
- 使用 Codex 进行读题、产品拆解、代码生成、接口契约核对、测试编写、调试与部署。
- OpenAI Docs 用于核对 JSON 输出的边界：合法 JSON 不保证符合业务 Schema，应用仍须校验字段、运算符、阈值和结构。
- 浏览器工具用于实际操作网页，验证主链路、异常、比较、保存和布局。测试记录只声明实际执行的操作。
- 产品内语言模型与开发阶段 AI Coding 是两条独立链路。未配置模型授权时，产品明确标注本地语义规则，不伪称已调用模型。

## 实际发现与修正
1. 官方文档称缺少 Key 返回业务码2001，真实未授权请求返回HTTP200/code2003。修正为统一拒绝所有非零业务码，不依赖HTTP200判断成功。
2. 行情快照不含中文名，改从估值接口解析名称；没有名称则显示代码。
3. 波动率需要21个价格产生20个日收益率；修正门槛并用可手算的交替±1%收益率复核样本标准差与252日年化。
4. 负PE不能因小于正阈值而入选。零、负值和缺失分别保留为不适用于正PE筛选，不能补零。
5. 财报的报告期末与披露日分开；排除未来披露记录，按上年同累计报告期计算同比。非正基数不返回普通增长率。
6. 不将 OR 误编译成 AND；没有分隔的多个指标、含数字但未明确运算符的区间表达会要求用户改写，不静默改用默认值。
7. 用户编辑自然语言后，必须重新生成条件；编辑期间到达的旧请求响应通过版本号丢弃，避免旧结果覆盖新输入。
8. 使用同一份数据快照解释条件变化；读取新快照后不声称名单变化仅由条件修改造成。
9. 调整初版偏淡的文字颜色，提升关键解释与数字的对比度；按用户指定安装taste-skill并采用app-screen方向，见DESIGN_REVIEW.md。
10. MCP工具发现不等于自选账户写入能力。真实发现21项只读金融数据工具，接入实际读取；同花顺接续仅生成条件和官方脚本，不伪称同步成功。
11. 同花顺导出必须与当前执行条件匹配；用户改条件后禁止将旧候选名单冒充新策略结果。
12. 平板表格中绝对定位的无障碍标签造成外层横向溢出；将滚动容器设为定位上下文后，在768和390宽度复测通过。

## 本轮功能优先复核（2026-10-19）
- 先编写新增回归，实际复现5类问题：单位错误被忽略、附加未知要求被丢弃、非正PB/价格误入选、同日未来时点未识别、同披露日财报冲突未识别。修正后通过；源码见tests/audit.test.mjs。
- 模型试调用曾因新增未经确认条件被一致性校验阻止；增加预检条件集合约束后，默认模糊意图和显式2条条件均实际返回model引擎并通过。模型未通过时没有偷偷退回本地正常结果。
- 实际接入DeepSeek官方API：deepseek-flash，按当前文档使用JSON输出并禁用思考模式，避免输出预算消耗在推理内容。只保存模型名、状态与条件数量，Key仅服务端。
- 修正接口测试脚本：旧版probe未在parse HTTP502时退出失败，已补上解析状态与条件数量检查；新版check-web.mjs覆盖完整HTTP验收。
- 发现框架在跨站POST到达业务层前已返回403，验收区分预期安全拒绝与非预期入口失败，不要求这一拒绝必须由应用JSON返回。
- 用户反馈“文字多、信息少”后，增加真实逐条件排除贡献和股票定位，合并同指标证据并保留全部条件；字体改为中文系统字体优先、常规字重。
